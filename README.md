# payload-nike

A Nike-style ecommerce store built on **Payload CMS 3** + **Next.js 15 (App Router)**.
A single Next app serves both the storefront and the Payload admin panel; data lives in
PostgreSQL, payments go through Stripe.

Started from the official Payload Ecommerce Template and heavily reworked: a custom `Products`
collection with filters and variants, cart and checkout powered by `@payloadcms/plugin-ecommerce`,
a full user account area (addresses, orders, interests, settings), and catalog import from
scraped JSON datasets.

---

## Stack

| Layer | Technology |
| --- | --- |
| Framework | Next.js 15.4 (App Router, React 19) |
| CMS / API | Payload 3.73 (REST + GraphQL + Local API) |
| Database | PostgreSQL 17 (`@payloadcms/db-postgres`) |
| Payments | Stripe (`@payloadcms/plugin-ecommerce` + `stripeAdapter`) |
| Styling | Tailwind CSS 4, Radix UI, `class-variance-authority` |
| Media | Sharp, local storage |
| Tests | Vitest (integration), Playwright (e2e) |
| Package manager | pnpm |

Payload plugins in use: `plugin-ecommerce`, `plugin-seo`, `plugin-form-builder`, `richtext-lexical`.

## Quick start

Requirements: Node `^18.20.2 || >=20.9.0`, pnpm, Docker (for the database).

```bash
git clone https://github.com/gitFishe/payload-nike.git
cd payload-nike

cp .env.example .env      # then fill in the variables (see below)
docker compose up -d db   # PostgreSQL 17 on localhost:5432

pnpm install
pnpm dev                  # http://localhost:3000
```

On first run, open `http://localhost:3000/admin` and create the admin user.
`onInit` seeds the `countries` collection from `src/lib/countries.ts` the first time it starts
against an empty database.

### Environment variables

```bash
DATABASE_URL=postgres://postgres:1488@localhost:5432/jeffrey   # matches docker-compose.yml
PAYLOAD_SECRET=<long random string>

NEXT_PUBLIC_SERVER_URL=http://localhost:3000
PAYLOAD_PUBLIC_SERVER_URL=http://localhost:3000

PREVIEW_SECRET=<secret for draft preview>

STRIPE_SECRET_KEY=sk_test_...
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_...
STRIPE_WEBHOOKS_SIGNING_SECRET=whsec_...

COMPANY_NAME=...
SITE_NAME=...
```

Forward Stripe webhooks locally:

```bash
pnpm stripe-webhooks   # stripe listen --forward-to localhost:3000/api/stripe/webhooks
```

## Scripts

| Command | What it does |
| --- | --- |
| `pnpm dev` | Next.js dev server |
| `pnpm build` / `pnpm start` | production build and serve |
| `pnpm dev:prod` | clean build + start locally |
| `pnpm generate:types` | regenerate `src/payload-types.ts` after schema changes |
| `pnpm generate:importmap` | regenerate the import map after adding custom admin components |
| `pnpm lint` / `pnpm lint:fix` | ESLint |
| `pnpm test` | integration + e2e |
| `pnpm test:int` | Vitest (`tests/int`) |
| `pnpm test:e2e` | Playwright (`tests/e2e`) |
| `pnpm stripe-webhooks` | proxy Stripe webhooks into the local app |

Always run `pnpm generate:types` after changing collections or fields, and
`pnpm generate:importmap` after adding admin components.

### One-off scripts (`pnpm payload run <file>`)

| Script | Purpose |
| --- | --- |
| `import.ts` | import products into `products` from the JSON files in `import-data/` |
| `scripts/backfill-plugin-price.ts` | re-saves products so the `syncPluginPrice` hook fills `priceInUSD` (in cents) |
| `scripts/reset-password.ts` | reset a user's password from the CLI |
| `scripts/seed-first-migration.ts`, `scripts/apply-interests-migration.ts` | manually mark/apply specific migrations |

## Project structure

```
src/
├── app/
│   ├── (app)/            # storefront: /, /shop, /products/[slug], /cart, /checkout,
│   │   │                 # /login, /create-account, /find-order
```

## Key pieces

**Products.** `src/collections/Products` defines the custom fields (title, productCode,
initialPrice / currentPrice / discountPercentage / currency, imageUrl, and a `filters` array with
type = color | size | gender | onSale). In `src/plugins/index.ts` these fields are merged with the
system fields generated by `plugin-ecommerce`, so the collection stays custom while remaining
compatible with the plugin's cart and orders.

**Pricing.** The storefront reads `currentPrice`, the plugin reads `priceInUSD` in cents. The
`syncPluginPrice` hook (`src/collections/Products/hooks`) keeps them in sync on save; existing
products are handled by the backfill script.

**Cart and checkout.** Cart state flows through `EcommerceProvider` + `CartProvider`
(`src/providers`), with `/cart` and `/checkout` pages including order confirmation and Stripe
payment. Guest checkout and order lookup without an account live at `/find-order`.

**Catalog and filters.** `/shop` builds queries via `buildProductQuery.ts` + `findProducts.ts` and
renders an infinite list (`ProductInfiniteList.tsx`) backed by an internal API route.

**Account area.** Addresses (with an `isDefaultShipping` flag added through an addresses
collection override), order history, interests, payment methods, and gift cards.

## Deployment

The repo ships a multi-stage `Dockerfile` (Node 22 alpine). It requires `output: 'standalone'` in
`next.config.js`. `docker-compose.yml` is meant for the local database only — in production point
`DATABASE_URL` at a managed Postgres instance.
